# Intent: the builds pass

The director, Nov 9 and 10. The last lines are from the design's gates.

- **A restart of the builds design,** so that the loot, formations and upgrades can be redesigned after it. A little of the current set worked and the rest didn't; design the set again with what's now known, rather than tweaking what's there. No build is kept for being there: add, remove, keep, trim or multiply as the design needs. The count is whatever comes out; twelve was fine for replayability.
- **What a build is doesn't change:** a way to play you can watch, with a rhythm, woven from threads, reached by more than one route, in rungs (`docs/gear-design/philosophy.md`).
- **Signposting and power at each phase of a run are among the things a build is judged by.** At rung 1 the content lets a player see the direction to push in, not the whole build. Each phase's step is worth taking. The path to the build never leaves the team unable to beat the content.
- **Every build manages survivability.** A constraint, not a design: how each build does it is the design's to say. It may turn out to be the real problem (every build might need a tank); if so, raise it.
- **What the sample's survivors did isn't a rule for what a build must be.** If the game only lets some kinds of build live, the game changes, not the builds.
- **Kits may change** where a build needs it.
- **Formations are important,** enough that a build pivots to match a good one. How they arrive in a run is a separate change, out of this pass; the formations have to work regardless.
- **Verdicts on the current builds** come from the state of play's table, not from this page. Lockdown fails on how rarely its window comes; Phoenix on dying being uncontrollable.
- **Kits arriving one ability at a time, and cooldowns carrying,** aren't judged until the game is balanced after this pass and we see which builds emerge.
- **Engines:** found synergies, designed in advance for players to find, on one or more roads. Many pre-designed happy accidents that work with a small number of pieces, so that a build doesn't only come online when all of its pieces are there, and so that builds have cross synergy and a player isn't just picking a build and doing only that. It's a design pattern, not a concept the player has to understand. The director's shield party is the first one found: it shows the size and the feel, and the rest aren't variations of it. They're picked as a game designer would, for being worth finding, not from a formula or a grid of build pairs, and the count is whatever comes out. Each is written as what combines and what the player sees, with no card text and no numbers.
- **Staying alive without a tank is an open problem,** to be thought about at this stage, and the answer may not lie in the builds alone. A wall at the start of every build would make the game feel the same every run, and so would needing a frontline fighter in a front seat: that constraint is the uninteresting part.
- **A status's base behaviour doesn't take on a build's identity** (`docs/rules.md`). No engine rests on a number the player can't see.
- **Whether Shock and Bleed have builds** is the design's to decide.
- **From the engines' first read:** if any one thing can be an engine on its own, it's a mythic, and that's allowed. The fallen don't stand up after a won fight: a knockout keeps carrying.
