# The interface

A browser interface on the headless engine, so the director can set up a party and watch the core set play, on a phone. It's a design tool, not Memory's game tab: nothing here runs in Memory, and the code stays small on purpose.

**Fourth version (Oct 24, 2026).** The director's review of the third asked for two things: an aesthetics pass with the art they supplied (tilesets, faces, weapons that show in the hand), and, more important, a fight that can be understood: statuses big enough to read and shown on the field, and the fight told one message at a time the way Dragon Quest and Pokémon tell it, with the log a tap away rather than the thing you read. This version keeps the third's bones (the double-bordered windows, the pixel font, the beats) and changes the field, the message window, the sheets and the art.

**The journey (Oct 25, 2026).** Having everything at once was overwhelming on the phone, so the interface now plays the progression experiment, the pack's campaign: it starts with the Knight, the Cleric, the Ranger, Neutral and the first run, and each run won opens the next and gives classes, formations and gear, once. Free play, the old sandbox, is a setting. See **The journey** below.

**The rogue mode (Oct 26, 2026).** A third MODE in Settings, beside the journey and free play: the core set as a roguelite on Slay the Spire's structure (`steps/05-core-set/5d-rogue/`). See **The rogue mode** below.

**The cleanup pass (Oct 26, 2026).** The director's list after playing: the explanatory sentences are gone (Settings, the journey's footer, the party screen's hint, the pickers' footers, the rogue screens' notes); a bestiary that says how tough a foe is and how each element lands; class sheets with a one-sentence line, an ability's cooldown and wind-up as whole numbers (in words since the director's later note: CD and CAST), and every amount with what it grows with ("150 LIGHT (125% MAG)"); tapping a unit in a fight opens its whole sheet; no seed for players (every fight and retry draws a new one); a fight's end and the campfire put their one big choice where the message window was, with the fanfare when the fight is won; the campfire at night on the field; NUMBERS in three sizes, medium the new default; a HIT PAUSE setting; big START and PARTY buttons; and an art pass with the packs the director uploaded (status icons such as Bleed, the rogue mode's statuses and weapons, the Witch and the Hellhound). The decisions it took are under **Decisions taken here**.

## Running it

- **On a phone:** every push to `main` builds it and publishes it to GitHub Pages at **https://pvaiun.github.io/memory-dungeon/** (`.github/workflows/pages.yml`). One-time setup in the repo: Settings → Pages → Build and deployment → Source: "GitHub Actions". On Android, Chrome's menu → "Add to Home screen" installs it as a full-screen app (`public/manifest.webmanifest`).
- **On the same Wi-Fi as a laptop:** `npm run ui` serves it and prints a Network URL; open that on the phone.
- **Locally:** `npm run ui` at http://localhost:5173. `npm run ui:build` writes `ui/dist` (ignored by git).

It's Vite and plain TypeScript, no framework. The game logic is the repo's engine, imported as is (`src/engine/`, `src/sim/`); the interface only reads the engine's state and its log. `npm run typecheck` checks it with `tsc -p ui`.

## The look

`src/pixel.ts` is the pixel grid, `src/style.css` the theme. The frame is 270 logical pixels wide; each logical pixel is a whole number of device pixels (`--u`), picked from the screen size, so nothing blurs: on a 1080-pixel-wide phone one logical pixel is four device pixels, and a row of the 8px font is 32. `1rem` is 8 logical pixels and the stylesheet sizes everything from it, so 33 characters fit a line.

Windows are the Dragon Quest kind: a dark fill, a light double border, light text. Colour carries meaning and nothing else: HP bars go green, yellow, red; MP is blue; a Shield is a pale segment on the HP bar; buffs are cool, debuffs warm; each element has its own colour (fire orange, ice cyan, lightning yellow, wind green, earth tan, light cream, dark violet) on its icon, its damage number and its ability's name; a gear code reads green when it raises a stat and red when it lowers one; powerful gear is gold. Settings offers a **day** theme (cream windows, dark text) with the same meanings.

The font is Press Start 2P (SIL OFL, `public/fonts/`); the field draws its numbers and words from the same font, rasterized once into 8×8 bitmaps, in any colour, with a dark outline.

## Screens

Every screen is its own layout: a header with ◀, windows, and lists that scroll inside their own window, never the whole screen.

- **Home:** the title, the party standing in its formation with their weapons in a strip of the road scene, then the menu, chunky and in the middle of the screen: JOURNEY (with the next run's name; FIGHT in free play), PARTY, CLASSES ("7 of 16"), BESTIARY ("12 of 36"), SETTINGS, each with a NEW tag when something inside is new. (A scene filling the space under the title was mocked up; the director kept this one.)
- **Big buttons:** a screen's main action is a big button at the bottom-centre, full width and tall, where a thumb finds it, its label in the screen's own 8px font (a doubled font read as blown up, not crisp), not filled and not flashing; the smaller ones in a row under it: START (REPLAY once cleared) and PARTY on a run's page, RUN ALL in free play, NEXT FIGHT at a fight's end, the campfire's choices, and in the rogue mode SET OUT, TAKE, ENTER, FIGHT, LEAVE, GO THIS WAY and DONE.
- **Journey** and **a run's page:** see below.
- **Fight** (free play only): the seven runs with a line each, then a run's fights with their foes ("Shield Knight, Centaur Archer ×2", ★ for the boss; tap one to play it alone), and RUN ALL.
- **Party:** party, formation and gear in one place, with no hint text: once a slot or a class is picked, **the places it can go pulse gold** (the other slots, or the classes). The same goes for an ability's number on a sheet (the other numbers pulse), the rogue mode's seats and its campfire swaps. The formation at the top with ◀ ▶ (tap its name for the list of ten with a line each). Three slot cards, each with its slot's name and stat changes (on the stat sheet's scale: a +2 step reads +20), the member and its name. One thing is selected at a time, a slot or a class in the roster below, and every move goes back to nothing selected: a slot then a class puts the class in that slot; a class then a slot does the same; a slot then another slot swaps them; the same slot twice deselects it; the same class twice opens its sheet, whose back returns here. A class already in the party swaps places with whoever it's put on. SHEET opens the selection's sheet, REMOVE takes it out of the party. Nothing stays selected when the screen is left.
- **Unit sheet** (from a slot, or CLASSES), laid out to be read: a head window with the face, the name, **the class in one sentence** (the interface's own line, `TAGLINE` in `src/content.ts`: the content's text opened with a role word, "Curser.", "Healer.") and the figure holding its weapon; a stats window as a grid of label-over-number cells (HP MP REG ATK / MAG ARM CRT AGG, plain: only an element's label has its colour) with the change gear and the formation make in green or red beside each, and the special stats under it; then one scrolling window with PASSIVE (icon, name, text), GEAR (each piece as its own sprite or icon beside its name, then for a weapon what it hits for, its kind, what that grows with and its cooldown, "33 PIERCE (23% ATK) CD 8", and the stat codes, then for a powerful or legendary piece what it does, in gold; every part wraps instead of being cut off at the screen's edge, so a rogue piece's long name and its five or six codes read in full, the same in every list that shows gear; tap for the picker), what the class can use, and ABILITIES as cards. The long second description is gone. A card: the number to tap in pairs to reorder, the icon at 1.5× (the director's middle ground between its own size and double; each of its pixels rounded to whole device pixels, so it's crisp but off the font's grid) **shaded the way the battle's rows draw it at a fight's start, with the ticks until it first comes round in the corner** (since step 5c the first slot starts a fight 20 ticks charged, the second 12, the third 6, so the order is part of a build), the name in its element's colour, then MP, the cooldown and the wind-up in words, "MP 24 CD 21 CAST 2", each a whole number of ticks (the director found the clock and swirl glyphs a different aesthetic from the rest: colourful icons where the game reads as type); the documents' sentence; and **its size for this unit with what each part grows with** (in plain text, not coloured by stat), MOBA-style: "150 LIGHT (125% MAG) + 10 BURN (MAG)", "72 SHIELD (60% HP)", "65 BLUNT (43% ARM) + STUN", "3×12 FIRE (25% ATK)", "+9 PER BURN" for Pyre's stacks, "8×CRT" for Backstab. The basic attack last, the same way. In designer view each effect is also spelled out with its target. ADD TO PARTY or REMOVE in the header.
- **Gear picker:** everything that fits, with the weapons' own sprites: a weapon's kind, cooldown, hit for this unit and what it grows with, and its stat codes on the stat sheet's scale; NOTHING for armor and amulets. The equipped piece is boxed in gold and says EQUIPPED. Tap to equip and return.
- **Classes:** the 16 with their faces and their line, to the sheet.
- **Bestiary** kept **as a Pokédex** in the journey and the rogue mode: an enemy not met in a fight yet is its silhouette and ??? (free play, the sandbox, shows them all), the home menu says how many of the 36 are met, and a newly met one has a NEW tag (here and on BESTIARY) until its page is opened (`src/bestiary.ts`; an install from before starts with every enemy of the journey's cleared runs met). The list has each enemy's likeness and name (gold ★ for a boss, orange for an elite), nothing more: what it's made of is on its page. A sheet: the sprite, the enemy's line, **HP, ATK, MAG and ARM** on the party's scale (so a high ARM says bring magic, and ATK against MAG says whether Armor or resistances help), **any element it resists or is weak to, in words, the way a class sheet shows one** ("FIRE −50%"; nothing when none differ, since the element icons don't carry enough to read as a row), **what it hits with** in words (its attack's kind and every kind its abilities deal, an element in its colour), what it can't be given, its passives, its actions as cards with their sizes from its stats, and the runs it's found in. MP, regen, crit and Aggro aren't shown; designer view adds them.
- **Settings:** MODE (JOURNEY, FREE PLAY or ROGUE), THEME, SPEED, **HIT PAUSE** (how long a fight holds on each message once it's typed: 25%, 50%, 75% or 100% of the base hold; 75% by default, the old hold is 100%), SOUND, MUSIC, AUTO NEXT, PARTY HP ON FIELD, **NUMBERS** (SMALL, MEDIUM or BIG; see **Numbers**), PORTRAITS (FACES, SPRITES or MIXED), DESIGNER, RESET JOURNEY and RESET ALL (each asks first). No sentences under them. With DESIGNER on: **SEED LOCK** (every fight plays one seed, shown with a NEW button, until it's off) and **CLEAR NEXT** (counts the next run as won without playing it and plays its celebration).

## The journey

The pack's `campaign` block is a road of about twenty runs, in order: the seven runs of the core set, with remixes (new runs from the same enemies) and trials (runs with needs on the party, like "Bring the Pyromancer" or "Stand in Escort") between them. `src/journey.ts` keeps where the player is, in its own localStorage key; the repo's `../src/campaign.ts` says what each run pays and what's owned at each point.

- **What's owned** is the start (Knight, Cleric, Ranger, Neutral, their plain weapons) plus what every cleared run gave. A class always comes with its plain weapon. Gear is owned or not: every class that can wear a piece can wear it at once. Nothing else changes: the menus only show less. The party screen's roster, the formation's ◀ ▶ and list, the gear picker and the class list show what's owned, with a line or a dashed **?** cell saying how many more there are to find. The bestiary shows every enemy.
- **JOURNEY** is the road as a list: cleared runs with a green √ (dim, still open to replay), the next run highlighted with ▶ and a NEW tag until it's opened, and the rest as numbered **???** rows, so the road's length shows but not what's on it. Each row has its number, name, a kind tag (RUN, REMIX in blue, TRIAL in orange) and its line.
- **A run's page** opens on **its ground**: a strip of the run's backdrop with the party (in its formation, weapons in hand) facing the run's boss and its followers, as the battle will stand them (free play's run page too). Then its line, the foes' change if it has one ("Every foe starts each fight Hasted."), its **needs as a checklist** against the party (√ green when met, × red when not), its fights the way the free-play list shows them (PRACTICE: tap one to play it alone), and the **reward**: a teaser by kind for the next run ("NEW CLASS · 4 GEAR"), the list of what it gave for a cleared one. The party and formation, then a big **START** (REPLAY once cleared), disabled while a need isn't met, and **PARTY** under it, whose back comes back here.
- **The campfire** (step 5b; RAISE, step 5c): every campaign run stops once, after half its regular fights. **The field turns to night**: the run's own backdrop washed dark blue, stars where it has a sky, the fire (the director's eight-frame campfire) in the middle lighting a stepped ring that breathes with the flame, and the party kneeling at it without their weapons, facing the fire, the fallen lying beside it. In the message window's place: CAMPFIRE, how many fights are done, and the choices as big buttons, **REST +40% HP**, **FOCUS +60% MP** and **RAISE <CLASS> 40% HP** for each knocked-out member; each member's HP and MP below. The pick answers the engine's campfire decision; the next fight starts after it. Nothing else restores between fights.
- **Clearing:** winning the last fight of the next run's whole run records the clear the moment the engine has it (before the story reaches it, so a reload can't lose it). Replays and practice fights pay nothing, and their summary says so; free play never pays. After a clear the summary's only way on is JOURNEY.
- **The celebration:** a window over the screen that pops in, with stars blinking around it and the gold title flashing, one card at a time (tap for the next; back or Escape skips to the last). CLEARED! with the party in their victory pose and the run's name (the win sound); then one card per unlock, each with the coin sound: **NEW CLASS** (its face and figure with its weapon at twice the size, its role, "FIND IT IN PARTY"), **NEW FORMATION** (its name, text and each slot's stat changes, "CHOOSE IT ON THE PARTY SCREEN"), **NEW GEAR** (up to four pieces a card with their sprites, codes and which classes owned can use each, "EQUIP IT FROM A CLASS'S SHEET"); then **A NEW PATH OPENS** with the next run's name, kind and line, and a JOURNEY button (or THE JOURNEY IS COMPLETE after the last).
- **NEW tags** (small, gold) lead from the menu to the new thing: on JOURNEY (a new run), PARTY and CLASSES at home, on a class in the roster and the class list, on the formation window (beside ▶) and in the formation list, on a sheet's gear slot when a new piece fits it (beside its ▶), and on the piece in the picker. They clear when the thing is looked at: a class when its sheet opens (with what it wears), formations when one is chosen or the list is opened, gear when the picker it showed in is left, a run when its page opens.
- **Two loadouts.** The journey and free play each keep their own party, formation and gear, so switching modes loses neither; an install from before the journey keeps its party as free play's and starts the journey with the starting three. Anything not owned (after a reset, or when the content changes under the save) is dropped on read: a party member that isn't owned leaves, a piece of gear falls back to the plain weapon or nothing, a formation to Neutral.
- **Backdrops** for the campaign's own runs (`cmp_*`) come from their enemies: the core set run they share the most foes with (each counted per fight, a boss three times) lends its scene; a small table by node id is the fallback (`themeOf` in `src/battle/scene.ts`).
- `window.__journey(n)` sets the journey to n runs cleared (nothing marked seen), for screenshots.

## The rogue mode

Settings → MODE → ROGUE. The home menu then shows ROGUE (the run's act, or how many leaders and wins) and, during a run, the run's PARTY. Its screens are `src/rogue-screens.ts`; the run is saved in localStorage after every step (`src/rogue-state.ts`), so a reload lands where the player was.

- **The leader:** the classes you own as a grid (the Knight, Cleric and Ranger to begin with; a won run adds its party), the picked one's sheet and the ability it starts with, the heat once a run is won, SET OUT.
- **The draft:** three class cards; the picked one's sheet below, with the ability it starts with and the two it learns later.
- **The map:** Slay the Spire's. The act and region in the header, the boss's name under it (tap it: the boss screen, its foes, their moves and how big they are before Armor), the party's faces with HP and MP bars, gold and supplies. Rooms are icons (a sword for a fight, a pink skull for an elite, a gold ? for an event, a flame for a campfire, a coin bag for the shop, a gem for a chest, a crown for the boss), joined by dotted lines; the walked path turns gold, the rooms you can reach pulse, and a tap shows what the room is and ENTER. Supplies are buttons under the map.
- **A fight's preview:** the foes, each with what it does (its abilities, and their size from its stats and the fight's knob, before Armor), what it hits with and what it resists; PARTY to re-gear before FIGHT.
- **A fight:** the battle screen as it is, with the party's HP and MP carried in and no retry: ONWARD after a win, THE CAMP STEPS IN after a loss with someone standing at camp, THE END after a loss without. Leaving mid-fight and coming back replays it from its start, the same way (each fight's seed comes from the run's, so a fight can't be rerolled by leaving).
- **The preview** shows each foe the way the bestiary does, with the fight's changes to HP and damage applied: HP, ATK, MAG, ARM, the element row, what it hits with, and its abilities with their sizes.
- **Spoils, a boon, a chest:** cards to pick one of, or skip, under PICK ONE right above them (it was in the header's corner, where nobody read it). Gear shows its rarity by colour (green uncommon, blue rare, gold ★ legendary), what a legendary piece does, and who in the roster it fits, or "NOBODY CAN USE IT YET" with the classes that could. An elite's trophy shows above, already in the bag.
- **The shop:** a scene of the shop at the top (a wood-panelled room composed from the town interior tiles: shelves of potions and books, a window, a painting, a counter of goods on a rug, the shopkeeper behind it, an unused robed figure from the enemy pack with its arms raised; the party in at the door), then BUY (cards with prices; a supply says BAG FULL when it can't be carried), TRAIN (learn or upgrade, as often as the gold allows, each one dearer), SELL (the bag).
- **The campfire:** the camp at night as a strip at the top (the battle's campfire scene, in the run's region); REST, FOCUS and RAISE as big buttons; TRAIN (learn or upgrade, the numbers before and after); SWAP (tap a party member, then one at camp; free, before and after the pick), with the boss a tap away; LEAVE once the pick is made.
- **Events, level-ups, the fork, the end:** a window of text and a list of choices; at the end, the road told as notes, then DONE adds a won run's party to the leaders.
- **The map:** the rooms within reach are drawn bigger (and pulse); a tap picks one (its name tagged under it) and **a second tap on it goes in**, or ENTER. The picked room says what it pays in a line ("GOLD · SPOILS", "MORE GOLD · A LEGENDARY · BETTER SPOILS"), with a big ENTER. The rogue screens' explaining sentences are gone.
- **Party, unit sheet, gear:** the party screen shows the formation (◀ ▶ over the owned ones), the three seats (tap two to trade seats), who waits at camp and the bag; between rooms, one standing at camp can stand in for a fallen member (IN FOR …) or fill an empty seat (TAKE A SEAT); the unit sheet shows the run's gear and the abilities learned, each with its size for this unit (two numbers to swap their order, the same number twice to leave one out of fights, LEFT OUT to bring it back) and those not learned yet; the gear picker lists the run's pieces that fit, legendary first, with who wears each (taking one from another member trades pieces).

**Scenes.** The run's moments are drawn in its region, on the battle's backdrops, by one small stage renderer (`Stage` in `src/battle/scene.ts`: a backdrop, the party posed with its weapons, foes, a chest or a fire, night, a sparkle): a fight's preview, the boss screen and each way at the fork show **the party facing the foes as the battle will stand them**; the campfire is **the battle's night camp at full size** (the party kneeling at the fire, the fallen lying beside it); spoils and a boss's boon show the party cheering beside what it won, laid on the ground (a gold sack from the iconset when there's gold, then each offer's own art: a weapon's sprite, a piece's icon, a tome's ability, a supply, a recruit standing among them), under a sparkle; a chest opens in front of the party with a sparkle (the dungeon pack's chest sheet); an event shows the party walking; a level-up shows the one who learns cheering; the run's end shows a cheer, or the fallen at night. A scene keeps its clock across a screen's redraws, so tapping a card doesn't restart the chest. The fallen lie down in every scene.

Settings gains GIVE UP THE RUN and RESET ROGUE in rogue mode.

## The battle screen

One field, 270×228, on a backdrop composed from the director's tilesets, one per dungeon (the road through the pines, the crypt's bricks and candles, the fire mine's lava brick and lava stream, the ice pass, the storm tower's blue stone, the deep crypt in violet, the tower top's battlements under rain and stars). **The party stands on the left at the packs' own size, with its weapons in hand; the foes stand on the right at theirs, which is bigger**: the director asked for the earlier scale (heroes at twice their size, monsters shrunk when crowded) to be inverted. A foe's sprite is never shrunk unless the fight has seven or more; small creatures (wisps, drones, mini slimes) are drawn small. Up to three foes stand in a loose triangle; four to six in a staggered front and back row; a boss stands in front with its followers to its left.

Every unit stands on a soft pixel shadow, which goes forward with a lunge and back with a wind-up's step. Over the field: a foe's thin HP bar under its feet, in the bar's colour with a pale Shield segment; **under everyone, their statuses as the pack's icons**, the 14×14 drawing of each without the tile's empty border, (recoloured per status: a red drop for Bleed, a flame for Burn, a snowflake for Chill, a shield for Guard, a chevron for Haste…) with the stack count in the corner, up to four per unit (a status that lands drops in from one and a half size; one that ends fades up and out); a thin wind-up bar beside the figure, upright and filling from the bottom (left of a party member, measured from the pose it's in so it clears the step back a wind-up takes; right of a foe), so it never covers the figure or the statuses of the unit above; damage numbers at double size that rise and fade (yellow with CRITICAL under them for crits, the element's colour for spells, a WEAK! or RESIST or SHIELD label), heals in green, a status's name with its icon when it lands; the VFX strips in colour. A hit flashes and shakes the sprite; a knocked-out foe fades when its defeat is told, not before: the engine settles a whole tick at once, so the HP bars, the party rows, the knockouts and the status icons follow the messages (an icon appears with its "gains" line and goes with its "wears off" line, with the engine's live stack count meanwhile) (each damage or heal event carries the HP after it), and two hits on one tick play out in order instead of the second seeming to strike a foe that's already gone; party members use their sheets' poses (chanting while winding up, the swing or thrust or bow-draw of their weapon kind, damage, dead, victory), and the weapon follows the pose.

Below the field: the **message window**, the party's rows, and the controls. (The list of the foes' names under the rows is gone: they're on the field, and a tap on one inspects it.) A party row has three columns: the portrait; the name with short HP and MP bars and their numbers; and **the actions' cooldowns**, big. Statuses aren't repeated here, since they show on the field under each unit and in the inspect window. The basic attack comes first, small and centred (it comes round fast), then a gap, then each ability at twice its icon's size, always in the same place. Each is shaded from the top by the share of its cooldown still to run, with the ticks left in the corner; it's outlined in gold when ready, and blinks while it winds up.

**The fight is told in beats** (`src/battle/narrate.ts`, `src/battle/battle.ts`), one at a time. A beat is one thing to read as a whole: an action and what it did, a status ticking, a knockout, at most four lines. **The window shows only the current beat, typed out a character at a time, and the engine's clock stops while it's read**; when the beat is done a ▼ blinks until the hold is over and the next beat replaces it, the way a Dragon Quest window does. A beat's lines come straight from the engine's log in plain English: "KNIGHT ATTACKS!" "BANDIT B TAKES 10." "PYRO CASTS FIREBOLT!" "BANDIT A TAKES 18 AND BURNS (7)." "CRITICAL! BANDIT C TAKES 15!" "KNIGHT DODGES!" "CLERIC USES PURIFY ON RANGER!" "BANDIT C TAKES 1 FROM POISON." "SNAKE A IS DEFEATED!" "6 WOLVES DRAW NEAR!" An action line carries the icon of its element or kind. **Tap the window** to finish the typing, or to move on to the next beat (on a paused fight, a tap plays one beat, so a fight can be tapped through like a Pokémon battle). **LOG** opens the whole fight so far with tick marks, over the screen, and pauses while it's read.

How long a beat holds comes from its weight: the typing at about 26 ms a character, then half a second plus a third of a second per line, times HIT PAUSE (75% by default), all at 1×; halved at 2×; at 4× the text appears at once and the hold is quartered. Between beats the engine runs at half a second per tick at 1×. The controls, one row of thumb-sized buttons with the tick at its end: ◀ menu, II pause, **STEP** (a mode, remembered across fights like the speed: the fight waits after every beat for a tap on STEP, the message window or Enter; it skips the dead time before the next beat, but while anyone is winding up it runs at the speed set, so the wind-up bar can be watched filling; ▶ leaves the mode, II only pauses), **one speed button** that goes 1×, 2×, 4× and round again, >> (plays the rest at once; the log still gets every line), LOG. Keys: space, Enter or n (advance), 1, 2, 4, s, l, Escape. **The phone's back button** (it works through one history entry the app adds only on a tap and steps back onto after each back press; Chrome skips entries added without a tap, which once made a second back leave the app) closes whatever overlay is open (a unit's state, the log, a sheet) anywhere; in the menus it goes back a screen like the header's ◀; in a fight with nothing open it asks LEAVE or STAY, so a fight is never left by accident.

**Inspect:** tap a unit on the field, a party row or a foe's name. The fight pauses and **the unit's whole sheet** opens over it, with what's happening to it now on top: for a party member its head (face, line, figure), HP, Shield and MP, what it's winding up and how long is left, its statuses (icon, name, stacks, ticks left, what each does), then its stats, passive, abilities with their sizes for its live stats and its gear (the cooldowns aren't repeated: the rows show them); for a foe its likeness, HP, statuses, then the bestiary's sheet with the fight's own numbers (the run's HP and damage changes included). Closing it resumes the fight.

◀ during a fight asks first (LEAVE or STAY). **A fight's end:** VICTORY or DEFEAT shows on the field with the fanfare and the victory poses **the moment the fight is won** (the engine logs a fight's end only when the run moves on, which had put the fanfare after NEXT). Then the message window's place takes **one big way on**: NEXT FIGHT (with which of how many), JOURNEY after a clear, the menu after a single fight, RETRY after a loss, or the rogue mode's ONWARD; below the party rows, the outcome (per member the damage dealt, taken and HP left) and the smaller buttons (MENU, AGAIN, LOG). In a run HP and MP carry over; AUTO NEXT (Settings) goes straight on.

**Seeds:** players never see one. Every fight, run and retry draws a new seed, so the same party never replays the same outcome by retrying; only the designer's SEED LOCK (Settings, designer view) plays one seed over and over. The rogue mode's fights take theirs from the run, as before.

## Numbers

The data stores every amount at 1,000 per point of the documents' 1–5 scale (`docs/core-set/README.md`). Settings → NUMBERS picks how many the interface shows per point (`NUMBER_SCALES` in `src/content.ts`): **MEDIUM, 30, the default** (a Knight has 120 HP, a plain sword hits for about 24, a boss has one to two thousand HP); SMALL, 10; BIG, 100. Measured over 84 runs of the seven core-set dungeons with mixed parties: at SMALL a third of status ticks and half of all heals showed as 1 or 0, so different amounts read the same; at MEDIUM 4% of ticks and 2% of heals do, while a typical hit stays a two-digit number (median 24, 90th percentile 54). An install on SMALL moves to MEDIUM once; BIG stays. Percent stats (crit, evasion, resistances, Lifesteal) show as they are, Aggro on its own scale, centred on 100, and status stacks as counts.

## Art

The packs are pixel art drawn at three image pixels per art pixel (the iconset at two). `ui/tools/assets.py` (Python with Pillow) builds `ui/public/assets/` from the packs, which is committed so the interface runs without them. It finds each pack by name anywhere under the folder it's given, so they can be unzipped as they come, and skips the ones that aren't there, keeping their committed output:

```
python3 -I ui/tools/assets.py <folder with the packs extracted> ui/public/assets
```

- **Classes** use the "Simple 8-bit Sideview Battlers" Style 2 sheets (RPG Maker MV layout: 18 poses × 3 frames), one per class, shrunk to their art size by the tool (a 144px frame becomes 48px), flipped to face right at draw time. The tool fixes two things in the pack: its **"chant" pose is drawn turned around on every sheet** (measured: each class's chant frame matches its wait frame only when mirrored), which made every class look backwards while winding up, so it's mirrored back, keeping the step back the pack gives it, and the weapon in hand moves back with the figure; and its **"item" pose is a placeholder of another sprite**, so it's replaced by "spell".
- **Weapons** come from the same pack's weapon sheets (and the standalone Weapon Pack for sheets the battlers' copy lacks): three 48×32 frames per weapon, drawn in the hand at the pack's anchor (the frame's bottom centre 12 pixels in front of the feet). `WEAPON_SPRITES` in the tool maps every piece of weapon gear to a sheet: daggers, swords, bows, spears and axes to a drawn one each, the staffs to a staff whose gem and glow are recoloured by the staff's element (the wooden shaft keeps its colour), and the rogue mode's eight own weapons (Headsman's axe, Stormbrand, Frostfang, Hunter's bow, Brand of kings, Gravecaller, Cinder rod, Earthshaker) to sheets of their own, where they had borrowed the plain ones. A rogue run's items show their base piece's art. Fist weapons show nothing. The attack poses run through the three frames; at rest the weapon is held (a bow close to the body).
- **Faces** are the humanoid face pack's 36×36 portraits, one picked per class (`FACES` in the tool: a face column and a palette row), used in the party rows, the party screen, the classes list and the sheets. The monster face pack is not used: the bestiary keeps the sprites' own likenesses.
- **Enemies** use one recolour each of the sideview enemy sprites (the Retro 8-bit Monster Pack, 300%, Style 2), as drawn. At run time `downscale` in `src/pixel.ts` takes one art pixel per block (the commonest colour, aligned to the art's own grid), so they keep their three or four colours; the few drawn small (`scale` ≤ 0.6 in the manifest) and crowds of seven or more shrink the same way with an outline; bosses never. The pack has sprites the first pass missed: the **Witch** is now the purple pointed-hood Hobzard and the **Hellhound** the wolves' red Fenrir, so both keep their names. Four are still renamed on screen to match the sprite that fits them, and only on screen: Archer → Centaur Archer, Shieldman → Shield Knight, Bat → Night Wyrm (no bat in the pack), Mummy → Crypt Guard (the content's Mummy "hides behind a big, old shield", which the Vanguard carries; Mythic Monsters I has a true mummy, in another style). The bestiary shows the screen name only; the "AKA … in the documents" line is gone.
- **Backdrops** are composed by the tool from the overworld, dungeon and castle tilesets (1x): `backdrop_*` functions tile a wall or a horizon and a floor and stamp pillars, candles, mountains and pines, one 270×228 scene per dungeon theme, plus the home strip. Indoors, the band where units stand is a plain tile dimmed by `darken`, so sprites, bars and status icons sit on a calm floor; the walls keep their pattern.
- **The iconset** (16 columns of 32px cells, 16×16 art pixels each) gives the armor and amulets their icons (`gearIcon` in `src/art.ts`) and the abilities their tags (an element, a sword, a spear, a hammer, a heart, up or down arrows, a shield).
- **Statuses** are the pack's 16px icons, recoloured per status by the tool (`STATUSES`: an icon number in the 400-icon set and a colour ramp), drawn on the field, in the party rows, in the inspect window and on the sheets, with the stack count in 3×5 digits in the corner. Bleed is three falling drops (it was a red potion). The rogue mode's 27 legendary rules and Refrain have icons of their own (an hourglass, a lantern, a skull, a padlock for the Silver bell…), and a legendary amulet shows its rule's icon as its art.
- **Chests** are the dungeon pack's object sheet (`!D_CHEST`, 16×16 cells, a chest per column opening down four rows); the rogue mode's chests are the gold one.
- **The campfire** is the director's small eight-frame sheet (`Small_sheet`, 32×32 a frame, at art size), drawn by the field and the rogue campfire's strip.
- **VFX** are the pixel effects pack's frames, packed into strips: an element's effect on magical hits, slashes, stabs, impacts, arrows and bites on physical ones, sparkles for buffs and debuffs, a heal, a revive, smoke for summons and splits.
- **Sound and music** are the director's: a retro effects pack and two tracks, converted by hand with ffmpeg to small mono mp3s in `public/audio/` (`src/battle/audio.ts` plays them). The menu track plays on every menu screen and the battle theme in fights, both looping. The effects: `tap` (a screen change) is "menu select"; `hit`, `crit` and `block` are the characters' medium, strong and fast attacks; `miss` is "zip"; `magic` (an element's spell lands) is "laser gun"; `cast` (a wind-up starts) is "question"; `heal` is the third coin pickup; `status` is "select sound"; `down` is "fall"; `win` is "cool thing"; `lose` is "embarrassed". SOUND and MUSIC in Settings switch each off. The director sourced them under a free licence. Browsers start audio only after a tap, so the menu music begins on the first touch.

`window.__gallery()` in the browser console shows every sprite with its weapon, every face and every status icon as drawn, for checking the art.

## Decisions taken here, for the director to react to

From the cleanup pass:

- **What counted as fluff:** every sentence that explains what the screen already shows or how to use it (Settings' paragraph, the journey's footer, the party screen's hint, "tap to change", "tap one to practise", the pickers' footers, "practice pays nothing", the leave dialog's text, the celebration's "find it in PARTY", the rogue screens' notes). What stayed is information the screen doesn't show otherwise: needs, rewards, a formation's effect, what a room or a supply gives (as short lines: "GOLD · SPOILS", "PARTY +30% HP"), the content's own descriptions. Two hints became states instead: picking an ability's number shows SWAP WITH? (in the rogue mode SWAP · SAME: LEAVE OUT, since leaving one out has no other cue).
- **The class lines are the interface's own sentences**, not the content's: the content's text opens with a role word and a long second sentence, and the documents keep both. Each one was checked against the class's kit.
- **When an ability first comes round** shows as the battle's own picture of it: the icon shaded by the share still to charge with the ticks in its corner, as the party rows draw it when a fight starts. The cooldown and the wind-up are words and a whole number each, CD and CAST (rounded: Absolve's 0.5-tick wind-up reads 1). CAST is the director's word, and the fight matches it: its messages say a unit readies a move and then casts or uses it, and inspecting a unit mid-cast shows CASTING and the ticks left.
- **Amounts show both numbers, the way a MOBA tooltip does:** this unit's size and the share of the stat it grows with, coloured like the stat. Stacks name the stat only (a share of Magic means nothing for a count). Physical kinds (SLASH, PIERCE, BLUNT) are pale and elements their colour, so the colour of the word says what defends against it (Armor, or that element's resist) and the colour of the stat says what to gear.
- **The bestiary shows HP, ATK, MAG and ARM**, not MP, regen, crit or Aggro: enough to tell a wall from a glass cannon and physical from magical, without a full sheet.
- **Inspecting in a fight opens the whole sheet:** no second tap. Live state on top, then the sheet; the party's cooldowns are left out since the rows show them.
- **HIT PAUSE** scales the hold after each message, the freeze that lets a hit land. If the director meant the hit flash and shake instead (240 ms), that's a one-line change.
- **MEDIUM numbers are the default**, at 30 per point (the director's "times 3").
- **The night campfire** reuses the fight's own backdrop, tinted, so every run's camp is its own place; the party kneels (the sheets' "dying" pose, which reads as resting by a fire) without weapons.
- **The rogue mode's fights still replay the same way after leaving**, since each fight's seed comes from the run: rerolling a fight by leaving it would undo the run's stakes. Everywhere else, a retry is a new fight.
- **Selection is quiet:** a picked card or row is a shade off its window with a thin gold edge, not a bright block; the big buttons don't flash.
- **Every class sheet in one order:** the head, the stats, PASSIVE, GEAR, ABILITIES (the rogue mode's sheet and draft, and the in-fight sheet, follow the journey's).
- **Lists wrap instead of cutting text off:** gear rows (name, codes, a powerful piece's effect), the journey's rows, the run lists, the formation list and the fights' foe lines.
- **Bug found on the way:** the rogue mode's party strip and party cards had HP and MP bars squashed to nothing by a flex rule; they show now.

From earlier versions:

- **The scale is inverted, as asked:** heroes at their art size (about 30 pixels tall), monsters at theirs (40 to 70). The field is tight for six wolves, so a crowd stands in two staggered rows and the back row's bars and icons draw over the front row's heads; the alternative, shrinking them, is what the director rejected.
- **One beat at a time, typed.** The window never scrolls; what it shows is the one thing happening now, and the log is a button. The engine still waits for the reader (the third version's model), and a tap advances. If 1× reads too slow or the typing too fast, the three numbers at the top of `src/battle/battle.ts` are the knobs.
- **Inspect pauses the fight.** Tapping a unit opens a window over the screen and stops the clock, because reading what's happening to a foe shouldn't race the fight; closing resumes it.
- **Statuses are the pack's icons everywhere**, at 16 pixels (64 on the phone), on the field under each unit and in the party rows: the director preferred them to the hand-drawn glyphs once bigger was the point.
- **Weapons show in the hand**, in every pose, from the gear equipped; swapping a sword for an axe changes the figure on the home strip, the sheet and the field.
- **The journey is the default**, for a new install and an old one; free play is one tap away in Settings.
- **A class and its gear are one NEW.** A class's tag in the roster and the class list also lights when new gear fits it, since its sheet is where the gear is equipped; so after a run that pays gear, several classes can show NEW until a picker with that gear is opened. New gear counts only once a class that's owned can use it, so a tag always leads somewhere.
- **Locked runs show only a number.** The road's length is visible (20 rows), not what's on it; a run's kind and reward show once it's next.
- **The reward teaser counts the plain weapon** a new class brings as one of the gear, since it's new to the player.
- **Practice is always open.** A run's single fights can be played with any party, needs or not, since they never pay.
- **√ and ×**, not ✓ and ✗: the pixel font has no check mark.
- **Faces for the party, sprites for the monsters.** The monster face pack would fit the bestiary, but mixing portraits and sprites in one list looked inconsistent; it's extracted-ready if the director wants it.

## Limits, on purpose

- Ownership is the journey's only: free play has everything available, as the core set says.
- Single fights start fresh; a run carries HP, MP and knockouts as the rules say.
- The interface reads the engine's log for what happened and its state for bars; it never changes a fight, so what it shows is exactly what `npm run smoke` plays.
- `window.__scene` and `window.__driver` are a running fight's field and engine side, for scripted checks. `window.__battle("old_road~ogre_bridge", seed)` starts a fight and `window.__go("party")` opens a screen from the console or a script, for screenshots.
